# 🏦 おこづかいバンク

小学生の子どもへの誕生日プレゼントとして作った、家族専用のデジタルギフト券&おこづかい管理アプリ。

名刺サイズのQRカードを子どもに渡すと、スマホで読み込んで自分の「銀行口座」が開きます。

- 🎫 **ギフト券**: 「おでかけけん」などを使うと親のスマホに承認リクエストが届く
- ⭐ **おてつだいクエスト**: 単価表からお手伝いを報告 → 親が承認するとポイント付与
- 💰 **おこづかい管理**: 親が預かる現金を円建てで記録(ネットバンキングごっこ)。子は「おかねにかえる」で現金化を申請できる
- 💸 **兄弟間送金**: メモ(なんのお金か)付きでリクエスト→親の承認で成立。受け取った側にはプレゼント開封演出
- 🔁 **券の譲渡・交換**: 子ども同士でギフト券をあげたり交換したり(親の承認制)
- 🎁 **サプライズギフト**: 親・祖父母がいつでも券やお小遣いをメッセージ付きで送ると、子どもの画面でプレゼント開封演出
- 🪙 **利息の日**: 毎週日曜にポイント残高へ単利付与(金融教育)
- ✏️ **算数チャレンジ**: 1日1問、レベルに応じた問題でボーナスpt
- 🔓 **レベル制アンロック**: 目標貯金 → 利息 → (将来)複利・模擬投資 と成長に合わせて機能開放

## 技術構成

| 要素 | 選択 |
|---|---|
| フロントエンド | HTML + Vanilla JS(ビルドなし、CDNのみ) |
| ホスティング | GitHub Pages(無料) |
| バックエンド | Firebase Spark プラン(無料): Firestore + 匿名認証 |
| 整合性の担保 | Firestore セキュリティルール(`rules/firestore.rules`) |

サーバーコードはありません。**残高の改ざん防止はすべてセキュリティルール**で行います:

- wallet(残高)の更新は、同一バッチで作成される取引ドキュメントとペアでなければ拒否(`lastTxnId` ペアリング)
- 取引元帳は追記専用(親でも変更・削除不可)
- 子は「送金・利息・クイズ」のみ、祖父母(giver)は「増額のみ」、と役割ごとに許可を絞る
- 利息は `lastInterestAt` が正確に7日きざみでしか進まないため二重付与できない

この性質は `test/rules.test.js`(40テスト)で証明しています。

## 初期セットアップ(1回だけ)

### 1. Firebase プロジェクト作成

1. https://console.firebase.google.com で新規プロジェクト作成(Analyticsは不要)
2. **ビルド > Authentication > ログイン方法** で「匿名」を有効化
3. **ビルド > Firestore Database** で「データベースを作成」(本番モード、ロケーションは asia-northeast1 など)
4. **プロジェクトの設定 > マイアプリ > ウェブアプリ追加**(ホスティング不要)で表示される
   `apiKey / authDomain / projectId` を `js/config.js` に転記

### 2. セキュリティルールのデプロイ

```powershell
npm install                 # 初回のみ
npx firebase login          # 初回のみ(ブラウザでGoogleログイン)
npx firebase use --add      # 作成したプロジェクトを選択
npm run deploy:rules        # = tools/deploy-rules.ps1
```

初回実行時に **「あいことば(セットアップキー)」が自動生成され `rules/setup-key.local.txt` に保存**されます。
この値はルール本文に埋め込まれてデプロイされ(クライアントからは見えません)、家族アカウント作成画面で入力します。

### 3. GitHub Pages で公開

```powershell
git remote add origin https://github.com/<あなた>/<リポジトリ名>.git
git push -u origin main
```

GitHub のリポジトリ設定 > Pages > Branch: `main` / `(root)` を選択。
数分後 `https://<あなた>.github.io/<リポジトリ名>/` で公開されます。

### 4. 家族アカウント作成 → カード印刷

1. 公開URLの `setup.html` を親のスマホ/PCで開き、あいことば・家族名・メンバーを入力
2. `print.html` で名刺サイズのQRカードをA4印刷(倍率100%・背景グラフィックON)→ 切り取る
3. 子どもの誕生日にカードをプレゼント 🎂
4. カードを読み込んだら **「ホーム画面に追加」** を必ず案内(下記「iPhoneの注意」参照)

## 日常の使い方

- **親**: `parent.html`(承認 / おくりもの / 残高そうさ / 券・クエスト管理 / 設定)
- **子**: `child.html`(ホーム / けん / クエスト / おくる / きろく)
- 祖父母を招待するには: 設定タブ > メンバー追加(おくる人)> 招待リンクをLINE等で送る(7日有効・1回限り)
- 機能の解放: 設定タブ > メンバー詳細のチェックボックス(目標貯金・利息など)

## iPhone / Safari の注意(重要)

データ(残高・券)はすべてクラウドにあり消えませんが、**端末のログイン情報(匿名認証の鍵)はブラウザ内**にあります。
iOSのSafariは約7日間開かなかったサイトのローカルデータを消すため、放置するとログインが切れます。

- 対策1: **ホーム画面に追加**(追加したサイトは削除対象外+毎日開きやすい)
- 対策2: 切れてしまっても **カードのQRを再スキャンすれば自動復帰**(カード=永続の鍵)
- カード紛失時: 親の設定タブから該当リンクを「無効化」→「再発行」→ 再印刷

## 開発・テスト

```powershell
# ルールテスト(Firestoreエミュレータ上で40テスト)
pwsh -File tools/test.ps1      # プロジェクト内 .jre のJava21を使う。システムにJava11+があれば npm test でも可

# ローカルでアプリを動かす(エミュレータ+静的サーバー)
npm run emu                    # ターミナル1: Firestore+Authエミュレータ
npm run serve                  # ターミナル2: http://localhost:5500
# → http://localhost:5500/setup.html を開く(localhostは自動でエミュレータ接続)
# あいことばはテスト用の「test-setup-key」
# スマホ実機から試す場合: http://<PCのIP>:5500/?emu=1

# E2Eスモークテスト(ヘッドレスChromeで セットアップ→登録→券→承認→ギフト→送金→クエスト→クイズ→印刷 を一巡)
# 事前: 上記のエミュレータ+静的サーバーを起動しておく
node test/e2e.mjs
# Node経由のChrome起動に失敗する環境では、先にChromeを常駐させてから実行する:
#   chrome.exe --headless --remote-debugging-port=9333 --user-data-dir=%TEMP%\chrome-e2e "about:blank"
```

- Firestoreエミュレータには Java 11+ が必要です。`.jre/` にポータブル版Temurin 21を配置済み(gitignore対象)。無い環境では `tools/test.ps1` 実行前に https://adoptium.net から入手してください。
- 取引履歴のグラフ表示には複合インデックスが必要です(`firestore.indexes.json`、`npm run deploy:rules` で一緒にデプロイされます)。作成完了まで数分かかることがあります。

## 無料枠について

Firestore無料枠は読み取り5万回/日・書き込み2万回/日。家族4〜6人の利用では1%も使いません。
Cloud Functionsは使わないため、**Blazeプランへのアップグレードは不要**です。
利息の付与はサーバーではなく「子どもがアプリを開いたときに未処理分をまとめて計算」する遅延実行方式です。

## 設計メモ

- 金額はすべて整数(円・pt)。浮動小数点は使わない
- 利率はベーシスポイント(bp)で保持: 100bp = 週1%
- `families/{famId}` のIDは推測不能な20文字。ID知識がなければ何も読めない
- 招待トークン = ドキュメントID(能力トークン)。`list` は親のみ、`get` はトークンを知っている人だけ
- 将来の拡張ポイント: `unlocks.invest`(模擬投資)、複利への切替、算数チャレンジの回答をサーバー側(親のみ読めるドキュメント)に置く強化
